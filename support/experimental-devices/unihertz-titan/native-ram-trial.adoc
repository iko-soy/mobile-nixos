= RAM NixOS trial

Status on 2026-10-16: *run once with the owner's explicit approval; all four
questions were answered yes. See <<result,the result>>.* Each repetition needs
the owner's explicit approval of this exact procedure.

The link:native-diag-trial.adoc[diagnostic trial] showed the modern kernel's
view of the Titan: all eight CPUs, USB device mode in both directions, the
PMIC and the clocks come up. This trial starts the first NixOS userspace on
the phone: the link:ram-nixos/README.adoc[RAM NixOS] image boots the same
kernel from the recovery partition, with the eMMC controller disabled in its
board tree, receives the NixOS store over the USB network into RAM, and
accepts SSH from the Mac with one dedicated key. The original recovery is then
restored. Ubuntu Touch's boot and `dtbo` partitions are never written, and
Linux never sees the phone's storage during the run.

[[result]]
== Result (2026-10-16)

The owner approved the procedure and ran the partition reads, the entries, the
Volume Up start and the unlocks; watchers ran the fastboot steps and the push,
and the session ran over SSH from the Mac.

* *Preconditions.* The baseline found the battery full and charging, no update
  pending or running and empty recovery command directories. Step 2 found
  boot, recovery and dtbo identical to their preserved copies, and no control
  region changed since the latest copy.
* *Part 1.* `fastboot flash recovery` reported `Writing 'recovery' OKAY`, and
  step 7 read recovery back as `b05b933d...`, with boot and dtbo unchanged.
* *Question 1, yes.* After the Volume Up start the boot ROM and preloader
  passed through twice, and then the image's USB device appeared. Stage 0
  bound the gadget on `11201000.usb`, found no block device, and brought up
  `usb0`; macOS accepted the CDC NCM link and took the lease 172.16.42.2. The
  store arrived over TCP and was verified against its pinned size and SHA-256
  13 seconds after stage 0 began listening, and NixOS started at 33.5 seconds
  of uptime.
* *Question 2, yes.* NixOS 26.11 reached the multi-user target six seconds
  after the handover, in the state `running` with no failed unit, and SSH
  accepted the dedicated key. Root was a tmpfs and the store the squashfs on
  `loop0` under an overlay; the only block devices were the loop devices and
  `zram0`. `usb0` had 172.16.42.1 on the gadget network driver, and only sshd
  and the DHCP server listened. All eight CPUs and 5.9 GB of RAM were
  available, the CPU temperature was 35 °C, the deadline timer was armed and
  kept on isolation, the hard-deadline helper was running, nothing had the
  hardware watchdog open, and the crash action was `reboot`.
* *Question 3, yes.* `systemctl reboot` over SSH removed the image's device
  within three seconds, the preloader passed through, and Ubuntu Touch booted
  (`bootreason=reboot`), about two minutes after NixOS had started.
* *Question 4, yes.* From Ubuntu Touch, `sudo /sbin/reboot bootloader`
  reached fastboot, the preserved original was written (`Writing 'recovery'
  OKAY`) and Ubuntu Touch returned. Step 13 read recovery back as
  `4dd1c1f7...`, with boot and dtbo unchanged throughout; of the control
  regions only `expdb` changed, as after every boot.

The session's summary, journal, kernel log and interrupts are in the private
evidence directory. Found along the way:

* The donor configuration sets `CONFIG_USB_MTU3_DEBUG`, so the USB driver logs
  every transfer: the journal holds 2769 such lines, they overwrite the
  kernel's 128 KiB log during any transfer, and they probably limited the
  push to about 8.5 MB/s. The next kernel build should turn it off.
* Stage 0's status line that lists the block devices came out empty because
  `ls` and `tr` are not among its busybox applets; the check itself uses shell
  globbing and is unaffected.
* NixOS enables its weekly `fstrim` timer by default; it never ran here and
  has nothing to trim without storage, but a configuration meant for longer
  sessions should turn it off.
* With no RTC driver the clock starts at systemd's build date.

This is the first NixOS userspace on the Titan, reachable over SSH from the
Mac, with the phone's storage invisible to Linux throughout. Not shown: NixOS
on storage, the display, input, charging, audio, radios or a boot without the
Mac.

== Questions

. Does the image start, bring up USB networking that macOS accepts (CDC NCM
  with a DHCP lease for the Mac), and accept the pinned NixOS store over it?
. Does NixOS boot on the Titan from that store, with systemd, networkd and
  SSH working, root in RAM and no block devices but loop and zram devices?
. Does a restart from the SSH session, or the 20-minute deadline, boot
  Ubuntu Touch?
. Does the restore work as before, from fastboot entered from Ubuntu Touch?

== Basis

* *Kernel and overlay.* Unchanged from the earlier native trials: `Image.gz`
  SHA-256 `461372e7dd4f98f1924ae9ecae0381731d75cd0cf92f5b6f3b30eddce59986d1`
  and the same recovery-DTBO table.
* *Board tree.* The Titan tree with only `status = "disabled"` added to the
  eMMC host (`/soc/mmc@11230000`), checked to be the only difference; DTB
  table `b41fe0d006af9c795e809115c53807a37a13eee0812d2ce1d5199e3e8bfcfb32`.
* *Stage 0.* A static busybox script as PID 1; see
  link:ram-nixos/README.adoc[the image record]. Ramdisk 864739 bytes,
  SHA-256 `5723d84e11378fc5a006e7b84af4eaa5d1aeb94a0cf9715fd74d268afdd3731c`.
* *NixOS.* A minimal NixOS from the pinned nixpkgs, aarch64 packages from the
  binary cache: store squashfs 109862912 bytes, SHA-256
  `26429d8f251636445aa8e74d2a8061b7dac1e801d8bd8e3cd60eaabb7fae448c`, pinned in stage 0.
* *Image.* The native layout and command line, plus `nbd.nbds_max=0` and
  `systemd.crash_action=reboot`: 16510976 bytes, SHA-256
  `aa1b6751f995c3a201bf2737a3a0ad656b4206d1986ba489e49a8da31c74222a`; padded to 33554432 bytes, `b05b933d10f17a927e6d8bd3e132d20a3d40cb12f24cc836a50a1397d2d8d240`
  (`tools/flash-recovery.py --profile ram-nixos`).
* *Checks.* The VM build of the same stage 0 and configuration passes the
  valid, hard-deadline, storage and deadline cases (see the image record),
  and the phone build's binaries, busybox and pinned values are checked. An
  independent review's findings are fixed: among them, the kernel's built-in
  NBD devices would have made stage 0 refuse before USB came up.

== Preconditions

As in the link:native-diag-trial.adoc[diagnostic trial]: the owner present, a
direct cable, battery at least 60%, no update pending, no recovery command
file, both private copies of the original recovery (`4dd1c1f7...`) verified,
and a normal-mode control-region copy right before the trial with `para`
matching the latest copies. From step 5 until step 13 passes: no system
update, factory reset, `reboot recovery` or Volume Up start other than step 9
and the rows below.

== Procedure

*Part 1: write the image.* Steps 1 to 7 of the
link:repo-kernel-trial.adoc[repository-kernel trial], with `--profile
ram-nixos` and the image
`native-ram-image-v1/UNTESTED-UNSIGNED-native-ram.img`; step 7
must read recovery back as `b05b933d...`, with boot and dtbo unchanged.

*Part 2: run RAM NixOS.*

[start=8]
. *Listen:* start `tools/ram-nixos.py` with the private copy of the store
  squashfs, its pinned size and SHA-256, a new private output directory and
  the dedicated key; and the ADB/fastboot watcher of the earlier trials.
. *Start, owner-run:* keep the cable connected, power the phone off from
  Ubuntu Touch, hold Volume Up and press Power, and release both once the
  unlocked-state warning appears.
. *Expected:* within about 40 seconds the image's USB device appears; if
  macOS asks whether to allow the new accessory, the owner allows it. macOS
  adds a network interface with the address 172.16.42.2, the helper pushes
  the store, stage 0 verifies it and starts NixOS, and SSH answers about a
  minute later.
. *Session:* over SSH, read-only inspection only, saved privately: the system
  state and failed units, the kernel log and journal, mounts, block devices,
  network, processors, memory, temperatures and the bound drivers. Then
  `systemctl reboot`, which restarts the phone into Ubuntu Touch. Without a
  session the deadline restarts it 20 minutes after the kernel started, and
  stage 0's helper at 25 minutes if that fails.

*Part 3: restore.* From Ubuntu Touch, `sudo /sbin/reboot bootloader`
(owner-run); then, as in the earlier trials, write the preserved original
with the `original-recovery` profile, return, and read recovery back as
`4dd1c1f7...`, with boot and dtbo unchanged.

*Part 4: compare.* A normal-mode control-region copy after Part 3, compared
with the one from step 2 (`expdb` changes on every boot).

== Residual risks

* The modern kernel's earlier runs lasted 150 and about 45 seconds; this
  one may last up to 25 minutes with the CPUs at the bootloader's clocks, no
  frequency scaling, no thermal throttling and no charger driver. The session
  is mostly idle.
* The first userspace on the phone runs systemd and udev, which replay device
  events for every device the kernel found; with no kernel modules or
  firmware available, they can only adjust attributes of drivers already
  bound. Nothing in the configuration writes hardware settings, and the
  hardware watchdog is left untouched.
* The USB network path is new on the phone: NCM on Linux 7.3, macOS's NCM
  driver and its handling of a lease without a router were not exercised by
  the VM, which uses virtio networking.
* The eMMC controller is disabled in the board tree, so Linux sees no
  storage; stage 0 and NixOS both refuse to continue with a disk present. The
  eMMC stays as the bootloader left it until the restart.
* macOS adds a network service for the gadget, which stays in its settings
  after the run. The lease has no router or name server, so the Mac's own
  network use is unaffected.
* The hang worst case is unchanged: no feedback channel but USB, and no way
  out but the battery running down.

== What this can and cannot show

Success gives a NixOS system on the Titan, reachable over SSH, from which
further experiments can run without flashing. It does not show NixOS on
storage, the display, input, charging, audio, radios or a boot without the
Mac.
