This is the M0 collection procedure for the experimental Unihertz Titan port.
It applies to the original Titan running Ubuntu Touch. The owner has supplied
a runtime summary and inventory excerpts, recorded below. These identify this
phone's internal eMMC and partition capacities. Exact build provenance,
boot-image contents and recovery procedure still need confirmation.

The collector has automated host-side tests. The owner's excerpts are partial
hardware evidence; the complete probe report and raw inventory have not been
reviewed here. It does not establish a boot result for the experimental image.

The supplied `/dev/disk/by-partlabel` mappings associate the internal Android

Boot and recovery are each 32 MiB, matching the recipe's capacity requirement
and the previously built 33554432-byte reference image. This closes the measured
capacity comparison for this phone. It does not validate the installed image's
header, DTB layout, AVB metadata or acceptance of the generated image. A `dtbo`
partition is present; the supplied label listing has no separate `dtb` or
`vbmeta` label. That absence does not establish where those contents reside.

The mount excerpt associates `mmcblk0p36` with ext4 `/userdata` and `/nix`, and
`mmcblk0p33` with read-only ext4 `/android/vendor`. Root `/` is a read-only ext4
`loop0`; `/android/system` uses read-only ext4 `loop1`. Loop backing files and
free space were not supplied. An existing `/nix` mount does not establish a
sandboxed Nix build or a NixOS root filesystem. A future userdata-image design
must implement its own discovery/mount logic and preserve existing data.

Device-specific preservation targets visible in the label map include `nvcfg`
(`mmcblk0p6`), `nvdata` (`mmcblk0p7`), `nvram` (`mmcblk0p25`), `protect1`
(`mmcblk0p9`) and `protect2` (`mmcblk0p10`). This is not an exhaustive backup list;
no partition contents or backups were collected or verified.

== Collect directly over SSH

An SSH connection to the running Ubuntu Touch system is sufficient; no USB
connection or separate computer beside the phone is needed. Run the helper from
an environment that can reach the phone's SSH service, with Python 3 and OpenSSH
installed. The phone needs only its existing shell and standard system tools;
installing Nix on it does not change the collector's requirements.

Use the phone's reachable hostname/address and existing Ubuntu Touch account
(commonly `phablet`). First establish key-based authentication and verify its
host-key fingerprint through a trusted channel. Then, from the repository root:

[source,sh]
----
python3 support/experimental-devices/unihertz-titan/tools/collect-inventory.py \
  --ssh phablet@TITAN_HOST
----

For a nonstandard port, add `--ssh-port 2222`. SSH configuration and an available
agent can supply the identity key. Use `--ssh-config /absolute/private/ssh_config`
to select a dedicated OpenSSH configuration with `ssh -F`, without changing the
default SSH configuration. This option requires `--ssh`; the helper still uses
port 22 unless `--ssh-port` is supplied, even if the configuration has a `Port`
setting. The helper requires an already trusted host
key (`StrictHostKeyChecking=yes`) and uses batch authentication with no terminal;
it cannot prompt for a password, decrypt a key interactively or accept a new host
key. It runs the same fixed probes as ADB, without privilege elevation. The SSH
destination is not intentionally written into the report. Output stays on the
machine running the helper, outside Git, with the private permissions below.

SSH reachability and authentication have not yet been verified against this
Titan from the development environment. The owner-provided summary above does
not establish which collection transport was used. A private LAN address
requires an existing network route or VPN from the collecting environment.

=== SSH through an authorized TCP forward

In a managed cloud environment, use its supported TCP forwarding workflow.
Confirm both VPN configuration and a TCP grant for the phone's address; HTTP
access permission alone does not grant raw TCP access. Establish a loopback
listener forwarding to the phone's port 22 through that workflow. A listening
port does not establish connectivity or authenticate the remote phone.

Keep the SSH identity, configuration, candidate host key and trusted-host file
in a private directory outside Git. For example, with an authorized forward on
`127.0.0.1:2222`, collect only the ED25519 server public key before authentication:

[source,sh]
----
umask 077
ssh-keyscan -T 10 -t ed25519 -p 2222 127.0.0.1 > /absolute/private/hostkey.candidate
ssh-keygen -lf /absolute/private/hostkey.candidate
----

Compare the fingerprint with one verified directly on the phone or through an
independent trusted channel. Stop on a mismatch or missing key. A key scan by
itself does not establish trust. Only after a match, put the verified key in
`/absolute/private/known_hosts` under the alias `titan-inventory`, in the format
`titan-inventory ssh-ed25519 BASE64_PUBLIC_HOST_KEY`.

A dedicated `/absolute/private/ssh_config` can then contain:

[source,text]
----
Host titan-inventory
    HostName 127.0.0.1
    User phablet
    HostKeyAlias titan-inventory
    HostKeyAlgorithms ssh-ed25519
    UserKnownHostsFile /absolute/private/known_hosts
    GlobalKnownHostsFile /dev/null
    IdentityFile /absolute/private/id_ed25519
    IdentitiesOnly yes
    BatchMode yes
    StrictHostKeyChecking yes
    ForwardAgent no
    ClearAllForwardings yes
----

Use a configuration you control: OpenSSH configuration can execute local
commands. Keep the private directory mode `0700` and its files mode `0600`.
Check authentication with the verified key, then collect without changing the
phone's SSH configuration:

[source,sh]
----
ssh -F /absolute/private/ssh_config -p 2222 -n -T titan-inventory true
python3 support/experimental-devices/unihertz-titan/tools/collect-inventory.py \
  --ssh titan-inventory --ssh-port 2222 \
  --ssh-config /absolute/private/ssh_config \
  --output /absolute/private/new-inventory
----

The collector does not intentionally record the SSH configuration path or
destination, but private OpenSSH error output may still include them. Review
stderr as well as probe output. Stop the local forward after collection; recreate
it and recheck the active grants after an environment replacement.

== Alternative: collect on the Titan itself

If remote access is unavailable, run the collector in a terminal on the Titan.
This mode needs neither ADB nor SSH. From a checkout of this repository on the
phone, use Python 3 already installed there, or enter a Nix shell to supply it:

[source,sh]
----
nix-shell -p python3
python3 support/experimental-devices/unihertz-titan/tools/collect-inventory.py --local
----

`--local` reads the machine on which the command runs, so run it on the phone,
not on another development machine. It uses the same fixed probes and the current
user's permissions. Output stays in a private directory on the phone, outside
Git. Review `summary.json` there before sharing it. `--local`, `--ssh` and
`--serial` are mutually exclusive.

== Alternative: collect locally over USB

Run on the computer connected to the Titan, with Python 3 and Android platform
tools (`adb`) installed. Ubuntu Touch must already expose an authorized ADB shell;
check its developer settings if `adb devices` shows no usable device. The cloud
development environment has no attached Titan and cannot collect this remotely.

From the repository root:

[source,sh]
----
adb devices
python3 support/experimental-devices/unihertz-titan/tools/collect-inventory.py
----

With multiple ADB transports, explicitly select the Titan using the first column
from `adb devices`:

[source,sh]
----
python3 support/experimental-devices/unihertz-titan/tools/collect-inventory.py \
  --serial 'YOUR_TITAN_ADB_SELECTOR'
----

== Output and collected evidence

For every transport, the collector writes to a new directory under
`~/.local/state/mobile-nixos/titan-inventory/` (or `$XDG_STATE_HOME`), with directory
permissions `0700` and file permissions `0600`. To choose a destination, add
`--output /absolute/path/to/a/new/private-directory`.
Existing destinations and paths inside Git checkouts are rejected. ADB transport
identifiers are used to select the phone but are not intentionally recorded in
the report. Do not paste the output of `adb devices` into a public issue.

It reads a fixed set of interfaces using a local shell, SSH or `adb exec-out`.
It does not run `adb root`, `sudo`, `su`, reboot, recovery, unlock, flash, mount
or remount commands;
it does not install software or copy raw partitions. Starting ADB can start its
ordinary host-side server. Permission errors are retained instead of elevating
privileges. Each probe has a 20-second timeout, configurable with `--timeout`.

The ordinary collection includes:

* Kernel version and `/proc/config.gz`, when readable.
* Ubuntu Touch release, device-tree model/compatibility, and a small Android
  property allowlist covering model, build and reported verified-boot state.
* Partition names and block sizes, storage device types and SCSI driver names,
  mount table, filesystem support and memory map.
* Input enumeration with `Phys`/`Uniq` lines removed; framebuffer/connector
  geometry; USB gadget state; selected power-supply attributes; network interface
  names/status and ALSA cards.

Block `size` values from sysfs count *512-byte sectors*, regardless of the logical
block size. `/proc/partitions` uses KiB. Partition symlink listings show labels
and device nodes; they do not contain partition contents. The script does not
collect serial-number properties, IMEI, MAC-address fields, filesystem UUIDs,
full `getprop`, environment or `logcat` dumps. Runtime paths, mount information
and driver messages can still contain private information. Review all output.

To also capture kernel messages and command-line parameters, run another
collection with:

[source,sh]
----
python3 support/experimental-devices/unihertz-titan/tools/collect-inventory.py \
  --include-private-logs
----

Include `--local` when running on the Titan itself, or `--ssh phablet@TITAN_HOST`
when using SSH, in that command as well.

These additional files can contain serial numbers, addresses and other unique
identifiers. Keep the original collection private, review any excerpts before
sharing, and never commit the entire directory. No files are uploaded.

== Return the smallest useful result

Start by reviewing and sharing only `summary.json`. It contains kernel release,
model/device name and storage-type evidence. The collector identifies an eMMC
hint from an `MMC` device type and a UFS hint from a UFS SCSI host driver. An SD
card or a generic `sda` node alone is not enough evidence. Confirm the hint against
the internal partition map before selecting build inputs. Empty or inaccessible
interfaces yield an unknown result rather than a guessed variant.

Also report whether the collector marked any probes as unavailable or needing
review, and whether the Ubuntu Touch installation currently boots reliably.
If a specific missing interface matters, inspect `report.json` and the matching
`.stderr` file locally first. The report includes the exact fixed commands and
their return codes, but omits the ADB selector and SSH destination. Some shell probes inspect several
optional paths, so an exit code of zero does not mean every interface was present.
An overall zero exit status means collection completed, not that M0 passed.

For the next round, provide only reviewed excerpts of `storage.txt`,
`partitions.txt`, `android-properties.txt`, `device-tree.txt` and the relevant
kernel configuration. Do not post `config.gz` if it contains locally added
secrets or credentials. Log review must happen before publishing any excerpts.

== Compare the running kernel configuration

After collecting a readable `config.gz`, compare it locally with the `config`
from the pinned reference kernel output. Neither input needs to be copied into
Git. The comparison accepts plain Kconfig output or gzip-compressed output for
either input:

[source,sh]
----
python3 support/experimental-devices/unihertz-titan/tools/compare-kernel-config.py \
  --reference /absolute/path/to/reference-kernel/config \
  --runtime /absolute/private/inventory/config.gz
----

The tool hashes the decompressed configuration bytes, so the reference hash is
comparable with the build record in the README. It compares all parsed settings
but prints values only for a fixed list of boolean/tristate settings relevant to
the userspace and observed-driver audits above. Arbitrary configuration strings, source paths and
input filenames are not included in the report. Keep the output private and
review it before sharing.

An absent symbol is reported as unknown, separately from an explicit disabled
setting. A module setting does not establish that the matching module is
installed or loaded. Malformed, duplicate, empty or unreadable configurations
fail without printing their contents. Equal settings do not prove identical
kernels, sufficient backports, working syscalls, systemd compatibility or a
bootable image. Use the comparison to identify the next source/runtime checks;
it does not close M0, M1 or M2.

== Validate the helper without hardware

[source,sh]
----
python3 -m unittest discover \
  -s support/experimental-devices/unihertz-titan/tools/tests -p 'test_inventory.py' -v
----

Tests cover device selection, protected output destinations/permissions, storage
classification, timeouts, SSH destination validation/authentication options,
local-mode argument conflicts and the mocked transport boundaries. They establish
host-side behavior, not
compatibility with the Titan's ADB or SSH implementation.
