= Disposable VM USB lifecycle fixture

This is a build-only test of Linux configfs ACM with `dummy_hcd` and `cdc_acm`.
The emulated controller supplies both sides of the USB bus inside a disposable
x86_64 guest. No physical USB device, phone, macOS USB driver, network service or
USB passthrough participates. It does not run the imaging/transport pipeline.

[source,sh]
----
# Run on the x86_64 Linux builder, from the repository root.
nix-build support/experimental-devices/unihertz-titan -A usb.vmTests --no-out-link
----

On 2026-10-15, all five cases passed on the authorized x86_64 Linux builder
using Linux 6.18.38. Each guest reported its actual kernel release and the exact
expected stage markers, then powered off successfully. The Mac independently
rehashed all five downloaded 1 MiB disk fixtures; every hash matched the
recorded before/after hash. Kernel/initramfs hashes, per-case results and bounded
logs are retained privately. This is software USB lifecycle evidence only.

The separate `usb.vmRamdisk` contains a native static test PID 1, BusyBox and
the pinned VM kernel's virtio, dummy controller, configfs ACM and host ACM
modules. The callback is compiled only with both `TITAN_RESCUE_VM_TEST` and
`TITAN_USB_VM_TEST`. Its case selector and shutdown code are fixture-only.
None of these files is included in the production AArch64 rescue ramdisk.

== Ownership and readiness

The existing rescue PID 1 first validates its six RAM/virtual mounts and guards
the generated virtio disk read-only. After its VM callback handoff, the callback
owns a seventh, visible configfs mount under `/run` and creates only its fixed
fixture gadgets. It does not call the block producer or relax the production
source guard's six-mount policy.

Creating the ACM function registers `ttyGS0` before binding. The callback opens
that character device, verifies its sysfs/device identity, sets and verifies raw
termios, and retains the descriptor before writing `dummy_udc.0` to `UDC`.
After actual enumeration it verifies the host `ttyACM0` identity and synthetic
USB descriptors, then sets the host endpoint raw before exchanging bytes.
Fixture descriptor values, including `1d6b:0104` and the synthetic serial string,
are not proposed identifiers for a Titan gadget.

Cleanup explicitly unbinds with a newline write, closes owned TTY descriptors,
removes only the fixture's objects and normally unmounts its configfs mount.
Function removal must follow descriptor closure: the serial function's release
can wait for open descriptors. No lazy unmount or mount-namespace hiding is used.
Read-only configfs sealing is a tested phase inside this disposable callback;
it is not yet a production startup/mount policy.

The harness gives each guest a 90-second deadline and a combined 4 MiB console
and QEMU diagnostic bound. Guest polling has shorter monotonic deadlines, but
userspace cannot impose a hard deadline on every kernel open, close or configfs
operation. A stalled guest fails the host deadline. Logs and generated artifacts
are retained in the test output; keep copies private.

== Required cases

[cols="1,3",options="header"]
|===
|Case |Required observation
|`valid`
|Real enumeration, exact binary exchange in both directions with all 256 byte
values and fragmented writes, acknowledgement before cleanup, explicit unbind
and owned-object removal.
|`invalid-udc`
|A nonexistent controller cannot bind; no host ACM endpoint appears.
|`empty-configuration`
|A configuration without a linked function cannot bind or enumerate.
|`occupied-udc`
|A second gadget cannot take over the bound controller; the original endpoint
still exchanges the expected bytes.
|`disconnect`
|After proving two-way prefix connectivity, submit at most 4096 bytes of an
intended 131329-byte stream and unbind without sending its remainder or
completion acknowledgement. Any buffered host bytes must match that prefix;
both held TTY descriptors must report disconnection and the host endpoint must
disappear. This does not prove bytes remained in USB queues at unbind.
|===

Every case must complete its expected observations, restore the six-mount
baseline and power off the disposable guest. The writable host disk fixture's
complete SHA-256 must remain unchanged. Unexpected failure markers, missing
markers, timeout, diagnostic overflow or a changed disk fail the test.

== Remaining integration

These checks exercise the pinned modern Linux USB software stack. Titan uses
the vendor 4.14 MTU3 phone driver, not `dummy_hcd`. They do not establish Titan
USB role selection, macOS recognition, watchdog/charging behavior or boot/return
safety. No generated image has been booted on the phone.

Before combining USB and acquisition, define an explicit configfs mount policy
in both PID 1 and the source guard, with acquisition disabled during writable
setup/cleanup. Retain a supervisor that owns the gadget and all worker
descriptors through failure and completion. Source/transport completion and
host receipt must precede any successful teardown; a drained TTY buffer alone
does not prove that USB requests reached the host. Test the combined pipeline
and failure paths separately. Consistent userdata/calibration preservation and
a verified recovery route remain open gates.
